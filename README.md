# Carbay+

Carbay+ is a Laravel 11, Filament 3 and Livewire SaaS starter for Ghanaian car washing bays. It stores tenants in one MySQL database and scopes tenant-owned Eloquent models by `tenant_id`. The database queue table is `queue_jobs`, reserving `jobs` for car-wash jobs; keep `DB_QUEUE_TABLE` unset or set to `queue_jobs`.

## Local setup (XAMPP)

1. Start Apache and MySQL in XAMPP and create a MySQL database named `carbayplus` using `utf8mb4`.
2. Copy `.env.example` to `.env` if needed and set the MySQL host, port, database, username and password. The default XAMPP configuration uses `root` with no password.
3. Enable PHP extensions `pdo_mysql`, `mbstring`, `openssl`, `intl` and `zip`.
4. Install dependencies and initialize the database:

   ```sh
   composer install
   php artisan key:generate
   php artisan migrate --seed
   npm install
   npm run build
   php artisan serve
   ```

The root URL (`/`) is the public portal landing page, with separate entry cards for Workers, Managers, and company Admins/CEOs. Workers sign in at `/worker/login`; Managers use phone and PIN at `/manager/login`, and company Admins/CEOs use `/app/login`. Open `/superadmin` for platform administration. The seeded Super Admin can sign in at `/superadmin` with phone `0241786330` and password `1234`; change this password before exposing the app beyond local development. The sign-in form also accepts email addresses. To start using `/app`, sign into `/superadmin`, create a tenant at **SaaS management → Tenants**, and provide the initial CEO name, login email and password. Tenant creation provisions the company’s main branch and CEO account automatically. Use those CEO credentials to sign into `/app`. A Super Admin visiting `/app` is redirected back to `/superadmin`; Super Admin access is not granted to tenant data.

Both sign-in pages use the Carbay+ branded Filament theme. If you update Filament, republish its static UI assets with `php artisan filament:assets`, then rebuild the Vite assets with `npm run build`.

In `/superadmin`, use **Global reference data** to manage global vehicle categories, makes, models and services. **Billing → Branch add-on invoices** lets a super admin mark an externally paid branch invoice as paid.

In `/app`, tenant CEOs can review sales totals and branch/worker/service breakdowns, review completed jobs under **Company → Wash Sales**, manage branches and workers, activate global services with vehicle-category-specific price/share overrides, record expenses when `expense_tracking` is enabled, and update company/payment settings. Managers also have mobile-first **New wash job**, **Today's jobs**, cash reconciliation, casual worker check-in, and payout approval screens. Jobs store vehicle, client, services, payment, and worker assignments; worker shares are tracked in wallets and scheduled payouts appear in the approval queue. The package `worker_limit` is enforced against active workers across all branches; deactivating a worker releases that seat, and reactivation requires an available seat. With `fraud_flags` enabled, repeated non-empty Mobile Money or Paystack references create a **Payment review** flag without blocking sale entry; company owners and branch managers can mark signals reviewed or dismiss them. This detects duplicate references only and is not a payment-provider verification or a fraud determination. When `worker_pin_login` is enabled, workers can sign in at `/worker/login` with their company email, registered phone and PIN to view their wallet, earnings and wash history and request payouts; managers can set or reset worker PINs and payout schedules from the Workers resource. PIN sign-in is rate limited and uses a separate worker session guard. The PWA manifest and service worker avoid caching authenticated Manager and Worker pages. Tenants with `reports_export` enabled can download date- and branch-filtered sales and expense CSV reports under **Reports & data**. With `audit_trail` enabled, CEOs and branch managers can review immutable **Activity history** records; managers see only their branch. Sensitive values such as passwords, PINs and Paystack secret keys are excluded from audit snapshots. A manager's exports remain limited to their assigned branch, and expense rows are included only when `expense_tracking` is enabled. Sale totals are calculated server-side from the tenant's active service/category prices; payment methods must be both enabled in company settings and included in the package. Wash Sales reads completed jobs directly: clicking Complete in Today's Jobs makes the job appear, with service snapshots, worker allocations, company shares, payment status, date filters and totals. Open and cancelled jobs are excluded; manual sale creation is removed from this page. Completion does not confirm payment. Historical manual sales remain stored for existing reports and dashboard totals. Creating a tenant in `/superadmin/tenants` provisions its included main branch automatically. Tenant feature rows override package defaults. A branch within its enabled `multi_branch` limit is included; otherwise the app creates a pending branch add-on invoice and leaves the branch unpaid until an administrator confirms payment.

New Wash Job's **Scan plate live** opens the device camera and continuously reads a plate without taking or uploading a photo. OCR runs in the browser; the Tesseract worker and core are loaded from jsDelivr and the English language data is downloaded from the Tesseract data CDN (a connection is needed the first time and when the browser cache is empty). Camera access requires permission and a secure context (HTTPS or localhost). Video frames stay on the device. The scanner recognizes Ghanaian plate formats and asks managers to confirm scans below 70% confidence; the plate remains editable. An optional job photo can still be attached separately. The legacy authenticated `/manager/plate-scan` endpoint uses Plate Recognizer and requires `PLATE_RECOGNIZER_API_TOKEN`, `PLATE_RECOGNIZER_ENDPOINT`, and `PLATE_RECOGNIZER_REGIONS`; it is rate-limited and its scans are saved in `plate_scans`. Tenant Paystack keys are stored encrypted; enabling Paystack requires the `paystack` package feature, the tenant's Paystack toggle, and a valid key. The signed `/payments/paystack/webhook` endpoint confirms GHS charges and credits worker wallets only after successful payment. Paystack worker transfers are opt-in under Company settings and require a recipient code for each payout.

**Company → Subscription** shows plan usage and invoices. The daily `carbay:billing-cycle` command generates the current monthly/yearly subscription invoice and suspends a tenant after the configured grace period (`CARBAY_BILLING_GRACE_DAYS`, default 7); schedule it with Laravel's scheduler. Super Admins can adjust a tenant's plan and mark subscription or branch add-on invoices paid. The PWA caches a small offline New wash job draft page only; it stores plate and notes locally and never caches authenticated company data. Restore those details online and finish services, workers, and payment before submitting. English is the default interface locale; `resources/lang/tw.json` is an initial Twi translation stub.

The `/app` and `/superadmin` admin panels adapt to screen size: phones use a compact header, thumb-friendly bottom navigation, and a **More** menu for the signed-in user's available pages, while desktop keeps the full Filament sidebar. On supported mobile browsers, install Carbay+ from the browser menu or **Add to Home Screen** to launch the responsive panel in standalone app mode. The mobile shell respects iOS safe-area insets and does not cache authenticated admin pages.

Tenant-owned models use the `BelongsToTenant` trait. Tenant managers are additionally scoped to their assigned branch for branch-level records; tenant-wide company settings and service pricing are CEO-only.

Company onboarding automatically creates an **Admin / CEO** account and the main branch. The owner can create branch-assigned manager accounts under **Company → Managers**, deactivate accounts, or reset manager PINs. Managers sign in at `/manager/login` by choosing their company and entering their phone number and 4–12 digit PIN; successful login opens their branch's **Manager dashboard**, including worker management. Manager PIN login is rate limited and accepts active company subscriptions and valid trials. Admin / CEOs retain password login at `/app/login`. New and changed staff phone numbers must be unique across Admin / CEO, manager, and worker accounts, including other companies and inactive accounts. Ghana local and +233 formats are treated as the same number; duplicate entries show an error beside the phone field. Existing duplicate records are retained and must be corrected individually.

The platform footer credits **Designed and Developed by DALE QUIST [Enabl Technologies]**. DALE QUIST appears as plain text, underlines on hover, and links to `/superadmin/login`.

Superadmin can upload or remove the welcome-page wallpaper under **Landing page appearance** (`/superadmin/landing-appearance`). JPG, PNG and WebP images up to 5 MB are served through a public image route with a soft overlay, while the source files stay in private storage. Run migrations when deploying this setting.

Live plate recognition runs in the browser. Clear high-confidence readings fill the registration immediately; lower-confidence readings must match twice and require confirmation before saving. The scanner script loads outside the Livewire component root so client actions and scan results remain connected to the form.

The live scanner has zoom-in/out buttons and a slider. It uses camera zoom when supported, with a digital fallback up to 4x. The OCR crop follows the zoomed preview so the visible guide matches the area being read.

Company Admin / CEOs configure prices and company/worker percentages under **Services & prices**. Wash jobs use only active company/category pricing. The worker pool is split equally among assigned workers, with any rounding remainder assigned consistently, and calculated on the server. Workers have no individual percentage setting and managers cannot override the allocation. Recorded jobs retain their original price/share snapshots.

Under **Company → Ghanaian service pricing**, the Admin / CEO can choose **Standard services** or **Ghanaian wash menu**. The Ghanaian form groups Body, Under and Engine prices by vehicle type, displays their combined total, and supports extras such as vacuuming, polishing, waxing and blowing. Starter vehicle names are provided with blank prices for the company to fill in. Blank cleaning prices mean unavailable; zero means free. The company sets the Ghanaian menu's company/worker percentages once. Both menus are retained when switching, and new jobs, sales and customer bookings follow the active menu. Existing jobs retain their recorded prices. Run the pricing-mode migration when deploying.

Vehicle wash prices use an editable table, with horizontal scrolling on phones. Additional services have ready-made choices for carpet cleaning, vacuuming, interior/exterior/full detailing, seat upholstery, roof lining, dashboard and steam cleaning, odour removal, polishing, waxing, blowing and headlight restoration. Custom service names remain supported. **Add catalogue service to Standard menu** (previously **Activate global service**) adds a shared-catalogue service to the company’s Standard menu; it is not a third service system.

The Ghanaian menu starts with editable prices transcribed from the supplied wash-board image. **Fill missing prices from image** adds the template to an existing menu while retaining prices already entered. Household carpet cleaning and standalone vacuuming have no board prices and remain blank for the company to price. **Standalone cleaning** services have no vehicle category, work with either active menu, and can be recorded by choosing that job type in New Job; no number plate is required. Prices are per job. Company shares and worker wallet credits apply as usual.

Manager and worker account forms include **Upload image** and **Take photo** controls (JPG, PNG or WebP, up to 5 MB). Profile images are stored privately and shown on the relevant dashboards. Photo URLs require authentication and company/branch authorization.

Managers can install their portal from `/manager/login`; its dedicated manifest starts at that sign-in page and returns authenticated managers to `/app`. Use the same HTTPS ngrok hostname for sign-in and dashboard access. Expired manager sign-in forms return to a fresh sign-in page, and expired Livewire requests refresh the page without replaying the action.

Today's Jobs has a worker selector and settlement cards for completed, paid jobs created today. Cards show earned, paid and still owed, independently of the plate search. Confirm payment records the full displayed outstanding amount as cash or manual MoMo (reference required), updates wallet balances and preserves earnings history. It can record an early scheduled payout once money has actually been given. Existing pending requests/transfers must be resolved through Payout approvals first. Wallet-wide payouts are allocated to the oldest available earnings; job-linked payouts retain their assignment. Worker dashboards use the same settlement calculation. No transfer is initiated by this confirmation action.

The landing page offers Install Carbay+ using /pwa/landing.webmanifest (start URL /), Android/Chromium's native prompt when available, and Safari Home Screen instructions on iOS/iPadOS. Chrome's Install button waits for beforeinstallprompt; manual instructions are available separately. The user must confirm the browser's installation prompt. Use HTTPS on mobile devices. Existing manager/admin manifests retain their workspace start URLs. The install button hides in standalone mode and after installation; authenticated data is not added to offline caches. Manifest icons use same-host URLs and include a padded maskable Carbay logo for Android launcher shapes. Free ngrok interstitials can return warning text in place of manifests/icons: the service worker adds ngrok's documented bypass header to public app-controlled requests, but Chrome's native installer can fetch outside its control. Reliable installation requires HTTPS hosting without that interstitial. After changing an icon, an existing shortcut may need removal and reinstallation.

Service Agreement and Data Privacy appear under Legal in the Admin/CEO and Manager panels, with public /agreement and /privacy pages linked from the landing page. Shared text is defined in app/Support/LegalDocuments.php. Provider identity is Abidale Group through Enabl Technologies. Configure CARBAY_LEGAL_EMAIL and CARBAY_LEGAL_ADDRESS before adoption; CARBAY_LEGAL_REVIEWED defaults to false and should only become true after professional review and confirmation of actual operational arrangements. These pages do not record contractual acceptance, certify DPC registration, or implement automatic retention/deletion. A signed contract/data-processing agreement and appropriate compliance operations remain separate from the displayed draft notices.

Superadmin Company financial overview (/superadmin/company-overview) lists every tenant, including inactive companies with no activity. It supports name/email search, company status filters, current month by default, today/week/year/all-time and custom dates. Sales include completed paid jobs plus historical manual sales; job shares use saved service snapshots, and historical manual sales are shown separately without inventing a share split. Expenses are filtered by spent_at and payouts by paid_at. Company share minus expenses excludes unallocated legacy sales and is before taxes/unrecorded costs. Wallet owed now is the all-time ledger (valid credits minus settled payouts/debits), including unpaid payout reservations and open paid job earnings. Summary cards follow company search/status filters. The query aggregates each dataset before joining to avoid multiplying totals across jobs, services, expenses and payouts. Access is restricted to Superadmin both at the page and aggregate service.

Superadmin Settings (/superadmin/settings) replaces Landing Appearance; the old /superadmin/landing-appearance URL redirects there. The page manages main/dark logos, Home Screen icon, app name and browser theme colour, landing text/wallpaper, shared dashboard hero (original/image/gradient), image darkening, install-popup enablement/delay, and legal contact/review details. It also links to platform companies, finances, packages/features, service catalogue, users, vehicle references, billing and legal documents. Branding uploads are stored privately and served only through fixed public asset kinds. Square PNG app icons (512–4096px) are converted to 192px and 512px using PHP GD; removal restores bundled icons. Dynamic /pwa/{landing,admin,manager,worker}.webmanifest endpoints use the saved name/icons and preserve workspace start URLs. Existing installed apps may retain icons until their browser refreshes the manifest or they are reinstalled. Shared dashboard background overrides apply to Admin/CEO, Manager, Worker and Superadmin heroes. The migration preserves the existing landing wallpaper. Only Superadmin can save platform settings; legal approval requires a contact email and business address.

Superadmin Billing → Tenant subscriptions (/superadmin/subscriptions) shows every company, its assigned plan, paid-through date, trial expiry, outstanding invoices and effective access. Generate due invoice uses the company's plan; Manage plan/status opens the company editor. Subscription invoices records full cash or MoMo receipts with a required receipt/transaction reference and recording user. Duplicate receipts and repeat invoice confirmations are refused. Subscription payments (/superadmin/subscription-payments) lists manual receipts and Paystack attempts separately from washing-bay sales. Historical invoices marked paid before receipt tracking remain paid without inventing a payment method or receipt.

Configure Abidale Group's receiving MoMo number/name/network and Paystack secret key under Superadmin Settings. The secret is encrypted and never loaded back into the form; blank retains the key and disabling checkout stops new online payments. Set Abidale Group's Paystack webhook to the displayed /subscription-payments/paystack/webhook HTTPS URL. Admin/CEO can pay pending invoices from /app/subscription using hosted Paystack checkout (card or Ghana mobile money), resume the same pending checkout, or check an existing attempt. Callback verification and signed webhooks check invoice/reference/amount/currency before marking paid. Extra gateway receipts after another payment are marked Review for manual reconciliation; they do not create additional subscription periods. These fees use Abidale Group's key, independent of tenant Paystack keys and plan payment features. No recurring debit or money transfer is initiated by manual receipt confirmation. Actual payments require the provider account and keys to be configured; tests use mocked Paystack responses.

Expired/inactive subscriptions show a popup with billing access for Admin/CEO and a contact-your-Admin/CEO message for Manager and Worker. Credentials are still checked before showing staff notices; inactive individual staff and missing worker-PIN features remain denied. Work requests and worker payout requests are blocked after subscription/grace expiry; billing and sign-out stay accessible. Pending due invoices and expired paid periods warn during the configured grace period (CARBAY_BILLING_GRACE_DAYS, default 7); expired paid periods are checked on requests even if the billing scheduler has not run. Run Laravel's scheduler in production for daily invoices and suspension. Billing-page visits and Superadmin's Generate due invoice also process that company's due billing. Configure CARBAY_BILLING_EMAIL for payment enquiries. Run the subscription-payment migration on deployment.
